# 舵机、IMU 实时诊断与读取顺序对照

本轮完成本地候选代码、ARM64 主程序和模拟浏览器验证；没有连接实机、启动实际动作、刷写固件、发布软件或镜像。预览里的缺回包、温度、电压都是模拟值，不代表用户鸭子的实测。

## 实现与界面

- 用户根据预览明确指定诊断放在总览。最终在「控制中 / 调手感」上方新增内嵌诊断卡，默认收起常显状态；展开后就地切换舵机与IMU诊断，不跳转。舵机页恢复原调试/校准布局，明确点「开始调舵机」才接管；IMU页保留原方向与站姿标定。
- 舵机诊断汇总在线反馈、最高温度、最低电压、有效读取更新；异常提示可定位舵机。最终改为横排卡片：宽屏每组5张、共3排，窄屏3列或2列；每颗常显关键数据，选中详情在对应组下方展开，移除常驻侧栏。复用总览原有3D，详细参数与读取顺序分别折叠。
- 每颗常显角度、温度、电压、近60秒缺回包及状态。累计数与窗口数分开；实际发送请求才有分母，全总线坏校验不强行归到某颗。数据源、会话、计数回退和顺序变化重开窗口。
- IMU 独立展示来源、协议、身份、角速度、四元数、数据年龄、有效更新和最近错误。姿态数值与传感器健康各自有时效；未知字段留空。主机接受样本时间与更新率有来源标注，不冒充芯片内部采样率。
- native 保留原顺序默认值；新增 ID 升序、指定ID最后读取及恢复原顺序。只调整遥测，模型/关节/动作目标顺序及 IMU 协议规定的读取位置保持原样。
- 当前所有者必须确认策略停止、全部卸力、临时增益恢复，才允许保存与切换。共享 `servo-read-order.json`；确认实际生效后重新统计。旧主程序没有能力时只读提示。
- 恢复调试会话先核对可信配置及原增益基线；旧标记或配置损坏时保留现场，不接管、不启动主程序。相关回归明确检查零次 helper take、give-back 和 UART 调用。
- 总览展开、前台且诊断卡进入可视区时，严格布尔心跳 `diagnostics_visible:true` 启用既有缓存的约10Hz推送；收起、滚走、切页、隐藏或心跳失活停止快速需求。服务端只在可见总览路由接受标记，并独立处理多个客户端。收起头部按主程序及总览状态的真实新鲜度置灰，不把仅有Studio连接当作硬件健康。

## 后续实机对照

1. 安装候选前记录原版本、配置和读取顺序，确认设备停止策略、已卸力。安装不等于验证运动改善。
2. 先只查看15颗和独立IMU状态，不使能；确认字段来源、计数、有效数据年龄与实际相符。
3. 同一供电、接线、波特率、读取长度下，以原顺序静止观察完整60秒，保存每颗请求/应答/缺回包和总线错误。
4. 在守卫允许时改为候选顺序，等新统计窗口再观察同样时长；对比所有ID，检查是否只是把错误转移到另一颗。
5. 无改善恢复原顺序；任何走路、起身和翻滚测试另行由现场操作。软件排列测试不证明电气或机械根因已经解决。
