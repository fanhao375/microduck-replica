# ID200 安装方向独立核验

用户要求根据与 KISSQY 的对照结果推进修复。这轮只处理已确认的“ID200 被标记已验证但没有独立直立/前倾核验”及标定修正说明，不调模型、零位、量程、ODR、滤波或 MCU。

原生来源为 `0d0e3e0dc833a59549e936b07b6b654bbcace60a`，保留目前配对的完整四元数采集。Studio 来源为 `835551a`。两者在独立工作树修改。

## 原生契约

- API43；安装后原有客户端版本差只记录，不因版本号拒绝服务。
- `calibration-status` 增加 `imu_verification_contract: "upright_nose_down_v1"`。
- 总线与 I²C 均使用传感器原始坐标系的最新已接受 `SensorReading`。对候选 mount 检查直立残差 ≤5°，然后20秒内取得至少12°前倾、朝前误差≤20°的5次有效读数；错误方向或超时不保存，卸力/调用取消按既有逻辑中止。
- 禁止ID200确认后直接save_verified。总线协议绑定仅在核验成功后写入，失败不得更改任何标定字段。成功响应保留 `imu_check`，包含upright/nose_down/residual_tilt_deg；`upright.imu_source` 必须是实际来源。
- 每个完整采集周期更新传给核验的最新原始读数；任何采集失败不向核验传递旧读数。总线具备序号时，同一序号不能在前倾核验中重复累计；通用无序号协议仍按已通过新鲜度门槛的实际交易计数。
- 运行模式的IMU数据处理和模型输入保持不变。固件、配置、已保存mount与舵机标定由用户后续核验前保持原样。

## Studio 契约

- 保留 HOME 原地采静止/前倾。粗校结果显示俯仰、横滚和相对旧方向的总改变量，并说明参考姿态偏差也会折入安装方向；不修改求解数学。
- 保存前要求最新calibration-status明确支持上述contract；旧主程序提示需要安装API43配套主程序，不走旧的只确认保存路径。
- verify成功还需检查响应中的 `imu_check`：来源一致、直立残差在门槛内、前倾角达到门槛、方向误差在门槛内，再执行既有读回/finish。缺少证明不能显示独立验证通过。
- 不自动发站立、前倾、行走等动作。安装前做备份与回滚准备，需要模型关闭、确认卸力，保留所有用户标定及参数。

## 边界

方向核验不能证明步态或倒地起身已修好，也无法独立辨认机械参考姿态误差。完成软件验证后，只由用户按页面提示进行一次姿态核验，再另行对照运动表现。暂不改SFLP初始化与chip-epoch协议。
