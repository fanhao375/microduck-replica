# 舵机与 IMU 实时状态、读取顺序对照设计草案

状态：用户已确认并要求直接实施；本轮完成本地软件与模拟验证，不自动连接或操作机器人。

## 目的

在现有中控查看每颗舵机和 IMU 的真实状态，帮助定位 ID13 等固定位置的缺回包；保留原读取顺序，增加受控的通信顺序对照。查看页面不应抢占正在运行的主程序总线。

## 已核对的现状

- 基于 Studio 发布源 `17ce73e` 和 native 发布源 `eecac18` 阅读。
- `software/studio/web/servo.js` 已在每行显示温度；电压、参数和累计通信计数藏在选中行详情里。
- `software/studio/studio/servo.py:view_from_robotd` 有温度、电压、反馈年龄、累计缺回包和连续缺回包，但逐颗 asked/ok 以及刷新率、缺包率尚未提供，不能把未知值显示为 0%。
- 舵机页现有挂载流程自动调用 `servo.open`。新增状态浏览必须明确只读，不因看页面停止 robotd 或创建第二个串口读者。
- native 由标定关节列表构造读取 ID 列表，Sync Read 按传入列表打包。模型关节序、显示对应、写目标序均不能跟随通信读取列表一起改变。
- 用户截图为 ID13「丢97 / 问1957」，该统计窗口的未成功读取比例约 4.96%。另有 Sync Read checksum error 和 missing IDs [13]；这不能单独证明坏校验字节一定属于 ID13，也不能定位电气根因。

## 推荐布局

用户于本轮预览后明确调整：诊断信息放在总览的「控制中 / 调手感」上方；舵机和IMU页面专门负责原来的校准。本节取代此前把监控作为舵机页默认入口的安排。

### 总览诊断信息

总览 `#/` 与 `#/pad` 共用的页面，在 `TuneSection` 前增加内嵌诊断卡。默认收起，常显舵机在线数和IMU状态；展开后在原位置切换「舵机诊断 / IMU诊断」，不跳转页面。舵机诊断以列表和选中详情为主体，复用总览已有3D，不重复放一只3D。高级读取顺序仍在该卡内折叠。

舵机页恢复原调试/校准布局，仍需明确点「开始调舵机」才接管；IMU页保留方向与站姿标定，去掉本轮新增的重复健康卡。有既存调试会话时明确显示会话所有者，不擅自切换或卸力。

顶部汇总：在线数量、最高温度及对应 ID、最低有效电压及对应 ID、总线最近读取状态、数据更新时间。首次无样本与主程序离线分别提示。

用户最终指定单排横向滑动：15颗按左腿、右腿、头颈顺序放在同一条可横向滚动的卡片带，桌面与手机都不换行；保留原生触摸/触控板滚动、可见滚动条和左右箭头。卡片固定宽度，名称旁标明分组，页身不产生横向溢出。每张卡常显ID、名称、温度、电压、角度、近60秒缺回包率和状态；整卡可点，详情统一在卡片带下展开，默认不占高度。选中异常项时只横向定位卡片；实时更新不重置滚动位置。读取顺序折叠区仍在下方。

### 内嵌 IMU 诊断

在总览诊断卡的IMU标签里显示只读状态：

- 当前来源（总线 ID200 或 I²C）、已知的芯片/板卡、协议和固件身份。
- 有效样本更新率、数据年龄、就绪与过期状态。区分设备数据更新与网页刷新，不把 MCU 发布频率称为芯片采样频率。
- 机身姿态、机身三轴角速度、四元数；加速度和温度只在当前数据源实际提供并且单位明确时显示。
- 源支持的错误/无效/过期计数与最近原因；校验错误、缺回包和姿态异常分开，不将任何大幅运动直接标为漂移。
- 主程序未完成启动时仍展示现有独立 IMU / 舵机启动诊断，各自失败原因不互相替代。

## 刷新与统计规则

1. 复用既有约10Hz状态推送和主程序不可变快照；网页不新增轮询 UART，浏览状态不停止模型、不使能关节。
   总览卡仅在展开、页面前台且诊断卡进入可视区时发送 `diagnostics_visible:true` 心跳，启用舵机与IMU的约10Hz快照推送。收起、滚出、切页、隐藏或心跳失活立即停止该快速需求；后台只接受可见总览路由的该标记，并按多客户端独立记账。此标记不授予任何运动或串口所有权。
2. 温度、电压等显示最近一次有效数据和年龄；过期后变灰并明确标旧数据，断网不继续显示绿色实时状态。
3. 「缺回包率」口径是指定窗口内未获得可用应答次数 / 实际已发出的、包含该 ID 的读取次数。主机未发出请求、网页漏帧、录制缺帧不计成舵机丢包。
4. 全总线坏校验计数单独显示；仅能识别预期但缺少的 ID 时不编造逐颗校验错误归属。
5. 无请求分母显示「—」；不足60秒显示实际已观察时长。主程序重启、计数回退、数据源/会话/读取顺序切换后重开窗口，保留清晰的统计起点。
6. 窗口由后台有限内存维护；历史累计与最近60秒分别标注。重复快照不能重复累计，页面刷新不重置设备累计数。
7. 固定参数沿用当前安全的读取/缓存途径，注明时间；状态浏览不高频扫描全部 EEPROM。第一版只读展示参数。

## 通信读取顺序对照

- 默认保留原顺序；提供「原顺序」「ID升序」「指定舵机最后读取」三种方案，指定 ID 默认13。
- 只调整舵机遥测 Sync Read 的请求 ID 列表，收到的数据继续按 ID 归位。IMU 的首尾位置或独立完整四元数读取规则保持对应协议要求。
- 配置必须是同一组15颗舵机的排列，不允许重复、遗漏、未知 ID 或把 IMU200混入舵机排列。
- 只允许在主程序确认模型停止且全部卸力、临时参数恢复的条件下切换；切换前后回读实际方案。不同 UART 所有者都要遵守相同方案，不能只改网页直连而主程序仍用旧顺序。
- 切换成功才开始新统计窗口，页面显示实际生效顺序。保留「恢复原顺序」。不自动上力、不自动试走，不据软件测试宣称丢包已改善。
- 人工台架对照保持相同硬件、接线、供电、波特率、读取长度与时长，先卸力静止比较原顺序和 ID13最后读取。记录逐颗请求/应答/缺回包、总线坏校验和读取耗时，识别是否只是把问题移到另一颗。

## 验证范围

- 原顺序默认值、排列校验、IMU协议边界、按 ID 回填及模型关节序不变的原生测试。
- 未发送不计缺包、坏校验归属、会话重启/计数回退、重复快照、60秒窗口及未知分母的统计测试。
- 主程序运行与调试会话两种来源的字段映射；只有 IMU、只有部分舵机和启动失败时的独立诊断。
- 浏览器验证桌面/手机布局、数据变化实时显示、选中详情随数据更新、断线过期、来源标注及进入状态页没有总线接管调用。
- 第一轮完成本地代码与模拟验证；发布或实机重启/部署之前另按当时设备状态处理。真实丢包改善需实机同条件对照。

## 备选方案

- 仅把现有字段展开：改动小，但主程序模式仍没有可靠分母，无法满足逐颗实时缺包率。
- 直接全屏显示所有参数并高频重读：界面密集且会增加总线负担，不采用。
- 推荐本草案：常显关键状态，详情显示带来源的参数，利用原有回读补齐计数，通信顺序单独受控切换。
