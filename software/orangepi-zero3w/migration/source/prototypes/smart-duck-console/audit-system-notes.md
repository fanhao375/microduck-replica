## 本轮发现与系统页修正

### 1. 电池原型错误使用 3S

- 来源：`web/settings-battery.js:90-98` 明确支持 2S 或台架电源，HD-1910 最高 8.4 V。后端 `studio/battery.py:29-32` 为 2S 查表；`:176-178` 给出默认值与范围。
- 第一版原型固定显示 3S、11.8 V、12.6 V，并删成最低/满电电压两个输入，属于错误内容，不能解释为视觉简化。
- 已改系统页：2S / 台架预设、黄线、红线、负载电压线、偏移、万用表测量算偏移、提示音、恢复默认；读取公共 `P.state.batteryVolts` 与 `P.batteryPercent()`。实测输入上限 8.4 V，偏移 ±0.5 V。
- 首页、底栏、关节页电压由相应模块维护者同步。台架模式应只显示电压，不显示百分比。

### 2. 模型实际按七种用途分配

- 来源：`studio/models.py:25-30`；`web/models.js:39-42`、`:128-134`、`:442-451`。
- 第一版用单个 `modelSlot`，选用踢腿也会替换所谓默认行走；实际上用途为 `walk/sitstand/ground_pick/kick_left/kick_right/roulade/stand`，各自选用与恢复。
- 已改：七用途映射、独立恢复内置或默认停用、选用/主程序已加载/正在执行分开显示。导入记录保持“兼容性待校验”，不伪造部署契约检查，不允许选用待校验记录。
- 包格式来源：`web/models.js:420-429` 为 ZIP / tar.gz 部署包，包含 `policy.onnx`、`manifest.json`、`deployment-contract.json`，不是任意裸 ONNX。

### 3. 可改动作键与第一版不符

- 来源：`web/models.js:13-19`、`:455-464`，默认映射由 `studio/models.py:29` 提供。
- 真实可改键：A 捡取、X 前滚翻、LB 左踢、RB 右踢、十字下坐站；第一版增加 B/Y 并把 LB 当叫声，没有依据。
- 已改真实五键、左右踢分开、固定 Select 急停说明、绑定变更确认与按键捕获流程演示。按键配置保持单一入口，遥控页跳到这里。

### 4. 机器档案被误缩成只读标签

- 来源：`web/tune.js:261-267`、`:317-339`。
- 原有整鸭、躯干、头、左右腿重量、脚底材料、备注、保存重量及 JSON 导出均应保留。
- 已补本地编辑与导出。未填重量导出 `null`；原型未读取的真实 IMU 四元数与舵机零位导出 `null` 并标注来源，不编造标定数据。
- 模型指纹、训练轮数、训练版本、执行参数的来源：`web/models.js:145-151`、`web/tune.js:308-318`。原型将未知元数据保留为未提供，而不伪造数值。

### 5. AI 连接需草稿与就绪状态

- 来源：`web/settings-ai.js:44-46`、`:82-93`、`:101-103`；`web/ai-ui-state.js:10-14`。
- 第一版要求完整字段才能保存，保存后便可测试，漏掉草稿、清除 Key、改地址重新填 Key、未保存修改禁测试、清空对话。
- 已补上述流程。密码和 Key 输入值不写入原型状态；只保存非敏感配置和“已配置”布尔标记。更换提供商或地址时该标记失效。
- 文字试聊不能被描述为已接入实时语音，也不控制机器人动作。

### 6. 原生更新不能假定支持 A7Z

- 来源：`web/settings-updates.js:65-77` 只声明特定 20261027 Qinmo 基线，区分支持状态和运行身份。
- `a7z-readonly-studio.patch:83-86` 仅说明只读阶段限制 `robotd-update`；不能据此推断所有 A7Z 模式永久禁止，也不能推断当前运动模式就兼容通用更新。
- 已将 A7Z 主程序包兼容性显示为未核验，禁用直接安装/恢复。
- 网页更新来源：`web/settings-updates.js:46-61`。已展示检查→下载/上传→验证→安装→重启等待→模拟重连读回，明确是演示阶段，不将点击确认当作实际升级完成。

### 7. 配网需要找回地址和已存网络

- 来源：`web/wifi.js:389-398`、`:441-453`、`:459-480`。
- 已补已存网络逐项忘记、设备 IP / 主机名复制、换网断开与热点恢复流程。
- 热点地址由本仓库 `provision/cubie_provision.py:69-72`、`:372` 及原 Studio `studio/net.py:40` 均确认采用 `10.42.0.1`。第一版 `192.168.4.1` 无依据，已修正。

### 8. 日志不能删除诊断证据字段

- 来源：`web/app.js:727-739`：按分类过滤、步骤/卡在哪、原文、建议。
- 已补来源筛选和行内折叠详情，常态维持短句。保留搜索、级别、暂停、复制与诊断样例导出。

## 由首页、维护、体验模块承接的发现

- 首次上手：`studio/onboard.py:87-88` 六步为舵机零位、IMU 方向、写进主程序、配手柄、测急停、站走。`web/app.js:486-526` 未完成时显示、完成折叠；`:532-544` 直达；`:640-645` 预览方向限位和文件。第一版首页完全删除。应只在未完成时突出当前步骤，详细操作进入专页。
- 启动失败与不能走原因：`web/app.js:301-317`，`web/tune.js:110-167`。第一版只演示在线、断线、过期、维护，缺主程序未运行、启动阶段、卡住、拒绝原因。首页应显示当前阶段和下一操作；高级证据在运行诊断展开。
- 总线恢复：`web/app.js:260-291` 区分恢复会话、未知保持、串口冲突、孤儿会话、交还等启动、交还后未启动。`:501-509` 在标定重启断线中保留进度和失败。第一版交还即成功，不能保留这种错误状态模型。

- 第一版可选择 USB 音频输入输出和播放音量，但当前核对源码未找到这些可改配置的实现，不能宣称为现有能力。
