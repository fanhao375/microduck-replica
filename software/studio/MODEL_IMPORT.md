# 导入训练好的模型

打开 Studio 的「模型管理」，不用重新烧系统镜像。

1. 在训练电脑上找到同一次部署导出的模型目录。
2. 将 `policy.onnx`、`manifest.json`、`deployment-contract.json` 打成 ZIP、tar.gz 或 tgz。若导出时有 `deployment-execution.json`、`deployment-runtime.json`、`model-info.json`，也放在同一目录。不要混入训练日志、脚本或多个模型。
3. 选择部署包，可填写显示名称，点「导入模型」。部署包上限 64 MiB；展开后上限 256 MiB。
4. 导入通过只表示已经安装。先卸力，再在模型卡片选择用途，点「使用此模型」。页面等主程序确认实际模型路径后才显示成功。
5. 需要动作键时，点模型的「设置按键」，按一次实体手柄的动作键，或在「手柄按键」下拉框选择；占用的键需要确认替换。走路仍使用原来的站、走控制。

单独一个 ONNX 文件缺少动作用途、关节顺序、站姿和运行参数，不能直接当成兼容部署包。Studio 会检查文件身份和合同，再调用本机 `robotd validate-policy` 预检 ONNX。没有可用的预检程序时会拒绝导入，不会把解压成功当成兼容。

当前运行程序的基础站姿和舵机 P 参数在启动时确定。与现有基础站姿、P 参数或关节顺序不同的模型不能直接热切换，页面会给出原因；需要先完成相应的部署适配。

## 模型、动作、按键的关系

- 「已安装」：模型文件在库里；「当前选用」：该用途已经选择这个模型；「正在执行」：主程序正在运行它。
- 按键绑定到动作，动作使用当前选中的模型。可设置的键为 A、X、LB、RB、十字下。走路和独立站立不作为普通动作键绑定。
- 实体按键录入需确认已卸力、五键配置完整且为常规动作，并等待配置稳定两秒；若有直接起身等特殊动作绑定，使用下拉框分配，避免录入按键同时触发原动作。
- 「取消绑定」只清除该按键；「恢复默认按键」恢复五个键的默认动作，都不会删除模型。
- 「恢复内置」把某个用途切回初次记录的默认模型，导入模型仍留在库里。
- 内置默认不能删除。导入模型仍被当前用途引用时不能删除，先切换其他模型或恢复内置。

导入文件和显示名称存放于 Studio 的 state 目录；鸭子上通常是 `/var/lib/microduck-studio`。升级 Studio 时保留这个目录。默认模型文件保留在原安装位置。改名只改变显示名称，不改变模型身份。

## 更多动作（镜像自带之外的新动作）

上面的部署包只能替换镜像自带的七个用途。想给鸭子**多加**一个动作（比如群友训练的「抖一抖」、开源仓库里的「深蹲」），用侧栏的「动作」页（原来的「模型」页从动作页最下面「走路和站立模型」进去）。动作页把出厂的动作、走路和导入的动作列在一起，每个都能点播放让鸭子做、绑到手柄键上：

**跟着软件来的两个**：深蹲（开源仓库 Ley-WL/microduck-rl，Apache-2.0）和抖一抖（群友投稿，作者同意随 Studio 发布）放在 `studio/bundled-actions/` 里跟软件一起装。升级后第一次打开动作页，它们就在「我的动作」里，标着「还没装到鸭子上」，参数已经按包里的 `skill.toml` 填好，架起鸭子点「装上」就行。删掉了不会自己再回来，想要回来可以从动作广场下载再导入。

1. **导入**：点「导入动作包」，选一个 `.onnx` 文件，或者打成 ZIP / tar.gz 的动作包。导入只放进库里，不会改鸭子。
2. **装上**：填动作名（小写英文、数字、下划线，比如 `crouch`）和时长，点「装上」。Studio 把它登记进主程序，等主程序确认加载成功才算数；没加载成功会自动撤回，鸭子上的动作跟原来一样。
3. **用**：选中它点播放，鸭子就做一次（要先按 Start 站好）；「手柄」页的技能区也会多出它的按钮。点「设置按键」再点下面一个键帽，就把它放到 A、X、LB、RB、十字下其中一个键上（会替换那个键原来的动作，替换前会问）。
4. **卸下**：先把它占的键恢复出厂动作，再从主程序里撤掉登记。卸下后文件还在库里；要删除得先卸下。

**什么样的动作能装**

- 输入 61 个数、输出 14 个数（带记忆的模型也行：`obs / h_in / c_in → actions / h_out / c_out`）。
- 站姿和关节顺序跟复刻版一样。用本仓库训练流程训出来的就满足。
- 不需要部署合同。包里除了模型以外的文件（说明、许可、合同等）会被放进 `extras/` 子目录。原因：主程序看到模型旁边有 `deployment-contract.json` 就会去解析，解析失败时登记照样成功，但下次开机整套动作都起不来。
- 包里如果有 `skill.toml`（社区里在用的格式，`[[policy.skill]]` 一条）或 `action.json`，动作名、时长、指令、幅度这些会自动填好。

**参数怎么填**

| 参数 | 意思 |
|---|---|
| 时长 | 动作做多少秒，0.2–60 |
| 指令 | 动作进行时喂给模型的 3 个数。普通单次动作是 0, 0, 0；「蹲 / 站」这类开关式的模型写 1, 0, 0 |
| 收尾指令、收尾秒数 | 时长到了以后，再用收尾指令跑这么多秒，让它自己回到站姿，然后交还给走路模型。0 秒就是不收尾 |
| 幅度 | 模型输出乘多少再加到站姿上。**要跟训练时一样，一般是 1**。不填时主程序会用全局值（镜像里是 0.7），动作会做不到位 |
| 力度比例 | 舵机力度相对走路时的比例，一般是 1 |
| 能否连着做 | 动作进行中再按一次，做完是否接着再做一遍 |

**要知道的限制**

- 装上、卸下、换键之前鸭子要先卸力，跟上面选用模型一样。
- 主程序最多 30 个动作，这里最多允许登记 28 个，留出余量。
- 做动作时要先按 Start 站好；动作进行中主程序不做跌倒保护。**第一次做新动作请把鸭子架起来试。**
- 放到 X 键上时，按住会连着发，动作会一遍接一遍地做。
- 别处（比如手改主程序配置）加的动作会列在「别处加的动作」里，只能换键，不在这里删。
- 登记的参数存在主程序配置里，导入的文件存在 Studio 的 state 目录里，升级 Studio 都会保留。

## 开发验证

`tests/test_model_actions.py` 覆盖动作包解包规则和装上 / 改参数 / 改名 / 卸下 / 绑键，以及加载失败时的撤回。`tests/test_models.py` 和 `tests/test_model_package.py` 使用临时模型和假主程序，不接触舵机。`tests/test_models_e2e.py` 使用真实 HTTP、部署包解析、模型库和无头 Edge，测试中的预检器与运行接口明确替换为本地测试实现。这些测试确认软件流程，不代替实际模型在硬件上的运动验收。
